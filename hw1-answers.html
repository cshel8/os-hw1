Problem 2What interrupts buy, and what they cannot

(a) Programmed I/O. After starting each print, the processor checks the printer's status over and over until the record is done, and only then continues. How long does the whole run take, from the start until the 12th record has printed? What percentage of that time does the processor spend waiting?

Each loop takes 6 ms of computing and 4 ms of waiting, for a total of 10 ms. Since the program runs 12 times, the total execution time is 12 x 10 = 120 ms. The processor spends 12 x 4 = 48 ms waiting, which is (48 / 120) x 100 = 40% of the total time.

(b) Interrupt-driven I/O. After starting a print, the program goes straight back to computing. When the printer finishes, it sends an interrupt; the handler uses 0.5 ms of processor time and then the interrupted computation carries on. Because 4 ms is less than 6 ms, each print finishes during the next round of computing, so the program never waits. How long until the 12th record has printed and its interrupt has been handled? Hint: first work out the time between the start of one print and the start of the next.

With interrupt driven I/O, the time between print starts is 6 + 0.5 = 6.5 ms. The first print starts after 6 ms, so the 12th print starts at 6 + (11 x 6.5) = 77.5 ms. Adding the final 4 ms of printing and 0.5 ms for the interrupt gives a total execution time of 82 ms.

(c) Now the printer is slower: 9 ms per record. Still using interrupts, a new print cannot start until the previous record has finished and its interrupt has been handled, so the program sometimes has to wait. What is the time between the starts of two prints now? In a typical loop (any loop except the last), how long does the processor sit with nothing to do? How long does the whole run take, until the 12th record has printed and its interrupt has been handled,, and how does that compare with programmed I/O on this slower printer?

The time between print starts is 9 + 0.5 = 9.5 ms. Since the professor computes for 6 ms while the printer takes 9 ms, it sits idle for 9 - 6 = 3 ms during a typical loop. The total execution time is 6 + (11 x 9.5) + 9 + 0.5 = 120 ms. With programmed I/O, the total would be 12 x (6 + 9) = 180 ms, so interrupt driven I/O saves 60 ms.

(d) In part (c) the processor still sits idle every loop, even with interrupts. Name the technique from Chapter 2 that puts that idle time to use, and explain in two or three sentences how it would do so in this situation.

The technique is multiprogramming, which allows the operating systems to run another program while the current program is waiting for I/O. In this situation, the processor could use the 3 ms of idle time to work on another program instead of sitting idle while the printer finishes. Once the printer sends its interrupt, the operating system can handle it and resume the original program when appropriate.

Problem 3How fast is memory, really?

(a) A two-level memory has a cache with an access time of 2 ns and a main memory with an access time of 50 ns. Find the average access time when the cache hit ratio is 0.80, when it is 0.95 and when it is 0.99.

The average access time is calculated using 2 + (1 - hit ratio) × 50.
- At a hit ratio of 0.80: 2 + (0.20 × 50) = 12 ns.
- At a hit ratio of 0.95: 2 + (0.05 × 50) = 4.5 ns.
- At a hit ratio of 0.99: 2 + (0.01 × 50) = 2.5 ns.
As the cache hit ratio increases, the average access time decreases because the processor needs to access main memory less often.

(b) For the same two-level memory, what is the lowest hit ratio that brings the average access time down to 3 ns? Show the algebra.

Using the average access time formula, 3 = 2 + (1 - h) x 50. Subtracting 2 gives 1 = 50(1 - h), and dividing by 50 gives 0.02 = 1 - h. Solving for h gives 0.98, so the minimum cache hit ratio needed to reach an average access time of 3 ns is 98%.

(c) A three-level system has an L1 cache (1 ns, hit ratio 0.90), an L2 cache (8 ns, which finds 75% of the words that L1 misses) and main memory (60 ns, which always has the word). Find the average access time. Then find it again for the same system with the L2 cache removed, and say how many times faster the version with L2 is.

The L1 cache has a 90% hit rate, leaving 10% of requests to check L2. Of those requests, 75% are found in L2 and the remaining 25% require main memory. The average access time is (0.90 x 1) + (0.10 x 0.75 x 9) + (0.10 x 0.25 x 69) = 0.90 + 0.675 + 1.725 = 3.3 ns. Without the L2 cache, the average access time would be 1 + (0.10 x 60) = 7 ns. Comparing the two systems, 7 / 3.3 ≈ 2.12, so the version with L2 is approximately 2.12 times faster.

(d) Real programs routinely reach hit ratios above 0.9, even though the cache holds only a tiny fraction of memory. Name the property of programs that makes this possible, name its two kinds, and give an example of each from ordinary code (a loop, an array, a variable, a function call).

The property is locality of reference, which includes temporal locality and spatial locality. Temporal locality means a program is likely to access the same memory location again soon, such as repeatedly using a variable inside a loop. Spatial locality means a program is likely to access nearby memory locations, such as when reading elements of an array in order. These patterns allow a small cache to maintain a high hit ratio.

The world field requires 3 bits because each block contains 8 words (2^3 = 8). The slot field requires 5 bits because the cache has 32 slots (2^5 = 32). (d) A program updates two different words of the same cached block 200 times each, and then the block is evicted. How many times is main memory written for that block under write-through, and how many under write-back? Then suppose that, under write-back and before the eviction, a DMA module reads that block straight from main memory. What does it get, and why is that a problem?

Under write-through, main memory is written 400 times because both words are updated 200 times each, and every update is written immediately. Under write-back, main memory is written only once when the modified block is evicted. If a DMA module reads the block directly from main memory before the write-back occurs, it receives outdated data because the latest changes are still only in the cache. This creates a cache coherence problem since the DMA module does not receive the most recent values.

Problem 5Three ways to move a block of data

(a) Programmed I/O: the processor waits for each word, reads it from the I/O module and writes it to memory itself. How much processor time does the transfer use?

With programmed I/O, the processor waits for each word and transfers it into main memory itself. Since there are 4,096 words and each takes 2 µs, the total processor time is 4,096 x 2 = 8,192 µs (8.192 ms). The processor is occupied for the entire transfer.

(b) Interrupt-driven I/O: the device interrupts once per word, and each interrupt costs 0.6 µs of processor time (save state, move the word, restore state). How much processor time does the transfer use, and what percentage of the 8,192 µs is that?

With interrupt-driven I/O, each of the 4,096 words causes one interrupt that takes 0.6 µs of processor time. The total processor time is 4,096 x 0.6 = 2,457.6 µs. The percentage of the total transfer time is (2,457.6 / 8,192) x 100 = 30%. This means the processor spends 30% of the transfer time handling interrupts and can use the remaining time for other work.

(c) DMA: the processor spends 10 µs programming the DMA module and 5 µs in the one completion interrupt. How much processor time does the transfer use? The DMA module also borrows the bus for 0.05 µs per word (cycle stealing). What is the most that cycle stealing can delay the processor over the whole transfer, and why is a stolen cycle not the same thing as an interrupt?

With DMA, the processor spends 10 µs setting up the transfer and 5 µs handling the completion interrupt, for a total of 15 µs of processor time. Cycle stealing can delay the processor by up to 4,096 × 0.05 = 204.8 µs if the processor needs the memory bus during every transfer. A stolen cycle is different from an interrupt because it only temporarily delays the processor's access to the memory bus, while an interrupt requires the processor to stop its current execution and run an interrupt handler.

(d) Pick the most sensible technique for each device and give a one-line reason: a keyboard on a laptop; copying a 4 GB video file from an SSD; a toaster's temperature sensor read by a tiny processor that has no other work to do.

Keyboard on a laptop — Interrupt-driven I/O: The keyboard sends an interrupt when input is available, allowing the processor to perform other tasks instead of constantly checking for key presses.

Copying a 4 GB video file from an SSD — DMA: DMA is best for large transfers because it moves data directly between the device and main memory with minimal processor involvement.

Toaster's temperature sensor — Programmed I/O: The processor has no other work to do, so it can simply check the sensor repeatedly without needing interrupts or DMA.

Using the formula U = 1 - 0.75^n:

n = 1: U = 1 - 0.75 = 25.00%
n = 2: U = 1 - 0.75² = 43.75%
n = 4: U = 1 - 0.75⁴ = 68.36%

To reach at least 90% utilization:

1 - 0.75^n ≥ 0.90

0.75^n ≤ 0.10

n ≥ ln(0.10) / ln(0.75) ≈ 8.0039

Since n must be a whole number, the minimum is 9 programs.

Checking both values:

n = 8: U = 1 - 0.75⁸ = 89.99%
n = 9: U = 1 - 0.75⁹ = 92.49%

Therefore, 9 programs are needed to reach at least 90% processor utilization.

Problem 7How available is the service?

(a) What is the server's availability, as a percentage to three decimal places?

Using the availability formula, A = MTTF / (MTTF + MTTR) = 1500 / (1500 + 5) = 1500 / 1505 ≈ 0.99667774. Multiplying by 100 gives an availability of 99.668%.

(b) How many hours per year can users expect the server to be down?

Expected annual downtime = 8,760 × (1 - availability) = 8,760 × (1 - 1500/1505) = 8,760 × (5/1505) ≈ 29.10 hours per year.

(c) Keeping the same MTTF, what is the longest MTTR that still reaches "four nines" (99.99%)? Give it in minutes.

Using the availability formula, 0.9999 = 1500 / (1500 + MTTR). Rearranging gives MTTR = (1500 / 0.9999) - 1500 ≈ 0.150015 hours. Converting to minutes gives 0.150015 × 60 ≈ 9.001 minutes. Therefore, the maximum MTTR to achieve 99.99% availability is approximately 9 minutes.

(d) The company runs two identical servers, and the service stays up as long as at least one of them works. If failures are independent, the pair's availability is 1 − (1 − A)2. Compute it as a percentage to four decimal places. Which of the three kinds of redundancy is this?

Using the availability of one server, A = 1500 / 1505, the availability of two independent servers is:

A_pair = 1 - (1 - A)^2

A_pair = 1 - (1 - 1500/1505)^2

A_pair = 1 - (5/1505)^2 ≈ 0.9999889626

Multiplying by 100 gives 99.9989% availability. The two-server system is more reliable because the service only becomes unavailable when both servers are down at the same time.

The same bug would not normally crash the entire microkernel system because device drivers run as separate processes in user space instead of directly inside the kernel. (d) On a multicore computer, two cores become free at the same instant and both run the scheduler, which takes the first process off one shared ready queue. What can go wrong? Which of the design issues for multiprocessor and multicore operating systems does this show? Say what the operating system must do about it.

If both cores access the shared ready queue at the same time, they could select the same process or corrupt the queue. This is a race condition and demonstrates the need for synchronization and mutual exclusion in multicore operating systems. The operating system must protect access to the shared queue using a lock or another synchronization mechanism so only one core can remove a process at a time.

The handler loads the timer count of 0, adds 1, and leaves the AC containing 0001 (1). When the original program resumes, it adds -7 to 1 instead of 39, resulting in -6.
